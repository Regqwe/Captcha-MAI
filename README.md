# Captcha-MAI

Один рабочий контур: размеченные изображения → пять локальных распознавателей →
точность, задержка и проверка шести гипотез. Основная и единственная ветка — `codex/initial-experiments`.
Шестой ноутбук разбирает сохранённые ответы прежнего опыта Gemini. API-клиента,
платных запросов и повторных отправок в проекте нет.

Лучший измеренный локальный кандидат — **PP-OCRv6 small**: 1876/1984 правильных
строк (94,56%), медиана 25,3 мс на CPU в исходном измерении. На семи размеченных
целевых вырезках — 4/7; перенос на реальный поток не доказан. Повторные запуски
сохраняют точность и обновляют измеренную на вашем ПК задержку.

## Установка и запуск

Windows, Python 3.12, CPU. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 scripts/run.py review
```

`review` пересчитывает метрики из сохранённых настоящих ответов. Он не загружает
модели и не отправляет запросов. Для полного повторного локального эксперимента:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py benchmark
```

Команда проверяет и распаковывает данные, последовательно выполняет все шесть
ноутбуков тем же Python и обновляет их выводы, предсказания и сводные CSV.
Пять локальных моделей выполняют настоящий inference на 1984 holdout и 9 target;
Gemini читает только сохранённые ответы. При первом запуске локальных моделей
может потребоваться скачивание публичных весов. Настраивать Jupyter kernel отдельно
не нужно. Только распаковка: `python scripts/run.py prepare`.

## Где что находится

- `scripts/run.py` — единственная точка запуска: `review`, `prepare`, `benchmark`.
- `captcha_lab/` — подготовка данных, модели и единый расчёт метрик.
- `notebooks/` — ровно шесть основных ноутбуков, по одному на гипотезу.
- `datasets/` — полные архивы на 10 000 изображений, метки, аудит и целевые вырезки.
- `research/results/` — реальные ответы и эталоны в одном CSV на модель/набор,
  параметры запусков, сводные показатели, парные сравнения и примеры ошибок.
- `tests/` — проверка метрик и целостности рабочего контура.
- `requirements.txt` — прямые зависимости; `requirements-lock.txt` — точный
  состав зависимостей проверенного Windows-окружения.

Первые пять ноутбуков проверяют PP-OCRv6 tiny/small, ddddocr beta, CRNN и
Conv-Transformer. Шестой — только исторический результат Gemini с учётом
сетевых ошибок. Старые пилоты, копии ноутбуков, отдельные экспериментальные
ветки и отменённые расширения удалены из текущего дерева; история остаётся в Git.

1984 holdout-примера получены исключением 16 ранее просмотренных. Общие 200
выбраны до прогона. Ведущие нули хранятся строками. Обучение и подбор preprocessing
на test не выполнялись. Неизвестно, входил ли публичный корпус в обучение авторов
готовых весов. ADB, автоматический поиск области и принятие ответа сторонним
сервисом этим benchmark не проверялись.
