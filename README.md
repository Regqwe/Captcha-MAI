# Captcha-MAI

Распознавание текстовых капч на Android через USB ADB. Модель **PP-OCRv6 small**
работает на CPU компьютера; платные API и ключи не нужны. В проекте одна модель,
один ноутбук и одна точка запуска — `scripts/run.py`. Единственная ветка — `main`.

Подтверждённая точность: **1876/1984 = 94,56%** на публичном holdout.
На семи визуально размеченных целевых изображениях — **4/7**. Этого недостаточно,
чтобы обещать качество на реальном потоке; см. [Качество и ограничения](#качество-и-ограничения).

Скриншоты работы на телефоне: [docs/screenshots.md](docs/screenshots.md).

## Основная команда

Подключите телефон по USB, откройте форму с капчей и запустите из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile.json
```

Для [демоформы](https://2captcha.com/demo/normal) — `--profile phone-profile-demo.json`.

## Установка

Windows, Python 3.12. Команды выполняются из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

`requirements-lock.txt` — точный состав проверенного Windows-окружения;
прямые зависимости перечислены в `requirements.txt`. PyTorch и альтернативные
OCR-пакеты не нужны.

Первый запуск распознавателя скачивает публичные веса (~21 МБ); SHA-256 и размер
закреплены в `research/model.json` и проверяются автоматически. После загрузки
модель работает локально, изображение никуда не отправляется.

Сохранённую оценку модели можно посмотреть без загрузки модели:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py review
```

## Подготовка телефона и профиля

1. Подключите телефон USB-кабелем с передачей данных.
2. Включите USB-отладку, разблокируйте экран и разрешите подключение этого ПК.
3. Откройте настоящую форму с капчей и полем ответа.

## Запуск

Проверьте подключение: устройство должно иметь состояние `device`.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone-check
```

Сначала проверьте профиль без ввода и нажатий, затем включите обработку:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile.json --observe --duration 60
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile.json
```

Для демоформы откройте её в Chrome на телефоне и запустите:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile-demo.json
```

При нескольких устройствах добавьте `--serial СЕРИЙНЫЙ_НОМЕР`.
`--duration` ограничивает сеанс в секундах (0 — до остановки), `--output` задаёт
папку сеанса. Остановка — `Ctrl+C`. Экран телефона должен оставаться
разблокированным, а нужная форма — открытой. Наблюдение периодическое,
без автоматического перехода между приложениями.

Если в журнале после загрузки модели только `waiting`, это не зависание:
на экране не найден `title` выбранного профиля. Запись `waiting` показывает
ожидаемый заголовок и текущее приложение, а раз в 30 секунд пишется
`heartbeat` («Цикл наблюдения активен») с числом кадров — цикл жив.
Проверьте, что открыта нужная форма и выбран подходящий профиль.

## Как работает наблюдатель

Одна итерация: UI XML и снимок → проверка заголовка, подсказки и геометрии →
вырезка полной строки по ROI → два стабильных кадра → локальное распознавание →
проверка формата и score → повторное чтение экрана → ввод через найденный
EditText → проверка введённого текста → нажатие актуальной кнопки отправки.
Нет нажатий наугад, клавиши Back и промежуточных картинок в корне проекта.
Если WebView не отдаёт элементы, скрипт сообщает об этом и ничего не нажимает.

Правила безопасности:

- Одна картинка повторно не отправляется в пределах текущего экрана.
- Не более трёх отправок и обновлений за непрерывный эпизод; смена картинки
  не сбрасывает лимит. Состояние попыток между запусками не сохраняется.
- Если введённый текст не совпал с ответом, отправка отменяется.
- При неподходящем распознавании обновление возможно только через однозначно
  найденную кнопку `refresh`; если её нет, скрипт ждёт.
- Ожидание ответа — 12 секунд; повторная отправка того же ответа запрещена.
- Исчезновение капчи записывается как `screen_left_unverified`, **не как успех**.
  `accepted` ставится только после собственной отправки и найденного `success`;
  уже открытое сообщение об успехе обозначается `already_accepted`.
- После трёх ошибок связи подряд наблюдение останавливается.

Распознаватель поддерживает текстовые изображения; произвольные пазлы,
слайдеры и формы без доступных UI-элементов не обрабатываются.

## Проверки

Автотесты (24 теста, около 30 секунд, телефон не нужен). Проверяют метрики,
целостность данных, журналы и логику наблюдателя на синтетическом XML —
не точность OCR и не приём ответа внешним сервисом:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Распознавание готовой вырезки без телефона — в журнале появятся
`prediction` и `score`:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py predict docs/screenshots/02-roi-crop.png
```

Динамическая проверка на телефоне: распознавание открытой формы без ввода
и нажатий в течение 60 секунд:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile-demo.json --observe --duration 60
```

Реальные примеры из Drive (`datasets/phone/`, 2 изображения):

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone-eval
```

Полный повторный прогон точности и скорости на размеченных изображениях.
Команда проверяет SHA-256 картинок, выполняет ноутбук настоящим inference и
обновляет его выводы и `research/results/`. Ядро Jupyter выбирается из текущего
Python. Для работы с телефоном не нужна:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py benchmark
```

## Логи и диагностика

- Общий журнал всех команд: `runs/app.jsonl`; журнал сеанса телефона:
  `runs/<дата-время>/events.jsonl` или в папке `--output`;
  прогресс benchmark — `runs/benchmark.jsonl`.
- Консоль: время UTC, уровень, компонент, сообщение. Файлы: UTF-8 JSONL
  с полями `time`, `level`, `logger`, `message`, `status` и данными события.
  Исключения сохраняются с полным traceback.
- `INFO` — основные действия, `WARNING` — отклонённый ответ и лимиты,
  `ERROR` — сбои, `DEBUG` — чтение экрана, промежуточные состояния и время
  распознавания. Уровень: `--log-level DEBUG|INFO|WARNING|ERROR`;
  `--log-file путь.jsonl` меняет общий журнал.
- Ротация: 5 МиБ и три резервных файла (`.1`, `.2`, `.3`).
  Старые папки сеансов удаляются вручную. `runs/` не попадает в Git.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile-demo.json --log-level DEBUG
```

Для проверки границ картинки и доступных элементов сохраните снимок и UI XML:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone-capture --output runs/diagnostics
```

| Состояние | Действие |
|---|---|
| Нет устройства / `unauthorized` | Проверьте кабель, USB-отладку и разрешение на телефоне |
| `waiting` / `other_app` | Откройте нужную форму, проверьте приложение и заголовок профиля |
| `unsupported_ui` / `input_missing` | Проверьте UI XML и правила поиска элементов |
| `unsupported_layout` / `roi_outside_anchors` | Проверьте вёрстку, прокрутку и ROI |
| `rejected_prediction` | Проверьте вырезку, формат ответа и читаемость картинки |
| `input_not_submitted` | Текст в поле не совпал с ответом; отправка отменена, будет новая попытка |
| `attempt_limit` | Проверьте причину отказа; автоматических попыток больше не будет |
| `response_not_confirmed` / `screen_left_unverified` | Проверьте результат вручную и настройку `success` |
| `accepted` | После отправки найден настроенный признак успеха |

После устранения ошибки перезапустите команду.

## Состав

- `scripts/run.py` — единая точка запуска оценки, распознавания и ADB.
- `captcha_lab/model.py` — только PP-OCRv6 small, ONNX Runtime на CPU.
- `captcha_lab/evaluation.py` — реальный прогон, exact match, CER и Wilson CI.
- `captcha_lab/phone.py` — разбор UI, стабильность кадров и ограничение попыток.
- `captcha_lab/android.py` — подключение, чтение экрана, ввод и наблюдение.
- `captcha_lab/logging_config.py` — консоль, JSONL, уровни и ротация журналов.
- `notebooks/final_ppocr_small.ipynb` — единственный рабочий ноутбук.
- `phone-profile.json`, `phone-profile-demo.json` — профили экранов.
- `datasets/holdout/` — 1984 настоящих изображения с метками и SHA-256.
- `datasets/target/` — 9 целевых вырезок: 7 читаемых и 2 спорных.
- `datasets/phone/` — 2 размеченных примера из дополнения Drive.
- `research/results/` — ответы, эталоны, задержки и параметры модели.
- `research/comparison.csv` — сохранённое сравнение, по которому выбрана small.
- `docs/screenshots.md` — скриншоты работы на телефоне.
- `tests/` — автотесты.

Логика перенесена и исправлена из
[исходной папки](https://drive.google.com/drive/folders/1QQL9mCoTOBEysxFbRe2V1eLz_rij1iwx).
В старом `phone_bot.py` был отдельный PaddleOCR, обрезка правых 28% изображения,
удаление всех букв и запасные нажатия по фиксированным координатам;
`test_single_image.py` импортировал отсутствующую функцию; `test_local.py`
считал успехом ответ нужной длины без сравнения с меткой. Новый контур использует
ту же модель, что и benchmark. Старое исследование пяти моделей и Gemini
сохранено в [истории Git](https://github.com/Regqwe/Captcha-MAI/tree/43737f7).

## Качество и ограничения

Holdout: 1876/1984 правильных строк, exact match 94,56%, Wilson 95% CI
93,47–95,47%, CER около 1,02%. Медиана 25,4 мс на изображение на CPU;
текущие значения — `research/results/summary.csv`, версии и параметры —
`research/results/run.json`. Время включает открытие файла, preprocessing,
inference и decoding; загрузка и прогрев учитываются отдельно.

Target: 4/7, широкий 95% CI 25,05–84,18%. Семь меток прочитаны визуально,
два спорных случая исключены из знаменателя. Это development-набор, а не
независимая production-проверка. Ошибки и пустые ответы входят в знаменатель;
ведущие нули сохраняются.

Примеры с телефона (`phone-eval`): `558796` из полного экрана и `W9H5K`
из вырезки, 2/2 (`research/results/phone.json`). Метки прочитаны визуально,
набор использован при разработке.

На настоящем телефоне 1080×2400 подтверждены связь, чтение экрана, ввод,
нажатие и успешная проверка демоформы: модель прочитала `W9H5K`, скрипт ввёл
ответ, нажал Check и обнаружил `Captcha is passed successfully!`
(`research/results/adb-validation.json`). Одна и та же картинка проверялась
несколько раз — это проверка взаимодействия, а не оценка точности.
Медиана итерации 1–2,3 секунды плюс пауза опроса; это периодическое чтение
экрана, не видеопоток, и 25 мс OCR не равны задержке всего контура.
**Прохождение в целевом приложении из исходного задания не проверено.**

Сравнение на одинаковом holdout: small — 94,56%, ddddocr beta — 73,84%,
tiny — 49,09%, Conv-Transformer — 44,41%, CRNN — 33,52%
(`research/comparison.csv`). Обучение и подстройка preprocessing на holdout
не выполнялись. Автоматический поиск области произвольной капчи не реализован.

## Данные и происхождение

`datasets/holdout/images/` — 1984 JPG из test-части
[project-sloth/captcha-images](https://huggingface.co/datasets/project-sloth/captcha-images),
ревизия `eeaf2b6ec9086645f270f7e2aaa9ea90730683de`, лицензия WTFPL по карточке
источника. Метка — шестизначный префикс имени файла. 16 ранее просмотренных
изображений исключены (`datasets/holdout/excluded.csv`).
`datasets/audit.json` хранит аудит корпуса и SHA-256 манифеста; перед benchmark
проверяется SHA-256 всех 1993 проверочных картинок.

`datasets/target/` — 9 вырезок из предоставленных экранов 1080×2220,
область (0.10, 0.24, 0.93, 0.36). Метки, спорные кандидаты и хеши —
в `annotations.csv`. Полные исходные экраны и рабочий стол телефона
не публикуются; в `docs/` только демоформа. Неизвестно, входил ли публичный
корпус в обучение авторов готовых весов.

## Модель и источники

Путь данных: вырезанное RGB-изображение → BGR-вход RapidOCR → LCNetV4 + LightSVTR
→ CTC → строка. Детектор и классификатор ориентации отключены; обучающая
NRTR-ветвь при inference не запускается. Веса загружаются публично и не
распространяются в репозитории.

- [PP-OCRv6](https://arxiv.org/abs/2606.13108) — структура recognizer и отличия small/tiny.
- [Model card small](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_rec_safetensors).
- [CTC, Graves et al., 2006](https://www.cs.toronto.edu/~graves/icml_2006.pdf) — выравнивание последовательностей.
- [Ye et al., CCS 2018](https://eprints.whiterose.ac.uk/id/eprint/151526/1/ccs18.pdf) — адаптация к конкретному семейству капч.
