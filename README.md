# Captcha-MAI

Распознавание текстовых капч на Android через USB ADB. Модель PP-OCRv6 small
работает на CPU компьютера; платные API и ключи не нужны.

## Установка

Windows, Python 3.12. Команды выполняются из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

Первый запуск распознавателя скачивает веса (~21 МБ); SHA-256 проверяется
автоматически. После загрузки модель работает локально.

## Подготовка телефона и профиля

1. Подключите телефон USB-кабелем с передачей данных.
2. Включите USB-отладку, разблокируйте экран и разрешите подключение этого ПК.
3. Откройте настоящую форму с капчей и полем ответа.
4. Настройте `phone-profile.json` под эту форму.

Профиль задаёт приложение (`package`), тексты элементов (`title`, `footer`,
`input`, `submit`, `refresh`), формат ответа (`code_pattern`) и область картинки
(`roi`: нормированные координаты `[x1,y1,x2,y2]`). Для рабочего профиля укажите
точный `package` и признак успешного ответа `success`.

В комплекте: `phone-profile.json` — образец для шести цифр на исходной вёрстке;
`phone-profile-demo.json` — проверенный профиль [демоформы](https://2captcha.com/demo/normal)
в Chrome на экране 1080×2400. Прокрутка, масштаб или другая вёрстка требуют
проверки ROI. Полный цикл подтверждён на демо; целевое приложение требует
отдельной проверки.

## Запуск

Проверьте подключение: устройство должно иметь состояние `device`.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone-check
```

Сначала проверьте профиль без ввода и нажатий, затем включите обработку:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile.json --observe --duration 60
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone --profile phone-profile.json
```

При нескольких устройствах добавьте `--serial СЕРИЙНЫЙ_НОМЕР`.
Остановка — `Ctrl+C`. Экран телефона должен оставаться разблокированным,
а нужная форма — открытой. Наблюдение периодическое, без автоматического
перехода между приложениями.

## Логи и диагностика

- Общий журнал: `runs/app.jsonl`; журнал сеанса: `runs/<дата-время>/events.jsonl`.
- Консоль и файлы содержат время UTC, уровень и компонент; ошибки — traceback.
- `--log-level DEBUG` включает подробности; `--log-file путь.jsonl` меняет общий
  журнал, `--output папка` — папку сеанса.
- Ротация: 5 МиБ и три резервных файла. Старые папки сеансов удаляются вручную.

Для проверки границ картинки и доступных элементов сохраните снимок и UI XML:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run.py phone-capture --output runs/diagnostics
```

| Состояние | Действие |
|---|---|
| Нет устройства / `unauthorized` | Проверьте кабель, USB-отладку и разрешение на телефоне |
| `waiting` / `other_app` | Откройте нужную форму, проверьте приложение и заголовок профиля |
| `unsupported_ui` / `input_missing` | Проверьте UI XML и правила поиска элементов |
| `unsupported_layout` / `roi_outside_anchors` | Проверьте вёрстку, прокрутку и ROI |
| `rejected_prediction` | Проверьте вырезку, формат ответа и читаемость картинки |
| `attempt_limit` | Проверьте причину отказа; автоматических попыток больше не будет |
| `response_not_confirmed` / `screen_left_unverified` | Проверьте результат вручную и настройку `success` |
| `accepted` | После отправки найден настроенный признак успеха |

По умолчанию: до трёх попыток за эпизод, ожидание ответа 12 секунд,
остановка после трёх ошибок связи подряд. После устранения ошибки перезапустите
команду. Состояние попыток между запусками не сохраняется.

Распознаватель поддерживает текстовые изображения; произвольные пазлы,
слайдеры и формы без доступных UI-элементов текущим контуром не обрабатываются.
Команды `benchmark` и `review` относятся к исследованию и для эксплуатации не нужны.
